# Обновление Nginx — 12.11.2026

## Область изменения

Переход с Nginx 1.25.5 (`nginx:1.25-alpine`) на стабильную 1.30.6.
В Compose закреплены версия и неизменяемый digest официального образа:

```text
nginx:1.30.6-alpine@sha256:583b7f2fce1cdb8da5ad5c39ebd3c33b98b87d493190e548bdee1fa8c619c311
```

Проверенный image ID на TW, Linux amd64:
`sha256:1390db6b01a8b0c865b157c7f036b0772534418b1701f598737de546d208b6e4`.

В шести HTTPS-блоках `listen … http2` заменён на `listen … ssl; http2 on;`.
Маршруты, ограничения доступа, TLS 1.2/1.3 и правила выдачи документов сохраняются.
Предварительная загрузка в deploy читает образ из Compose; отдельного устаревающего тега в workflow нет.
Ошибка загрузки останавливает выкладку до остановки сервисов. После запуска workflow сверяет фактический
image ID контейнера с настроенным образом и выполняет `nginx -v` / `nginx -t`.

Основание: [стабильная ветка](https://nginx.org/en/download.html),
[изменения 1.30.6](https://nginx.org/en/CHANGES-1.30),
[синтаксис HTTP/2](https://nginx.org/en/docs/http/ngx_http_v2_module.html#http2).
Заявление о применимости каждой отдельной CVE к прежней конфигурации здесь не делается.

## Проверка кандидата на TW

Кандидат запущен под отдельным именем `insflow-proxy-canary-20261112`:
без публичных портов, с ограничениями 128 MB / 0,35 CPU и всеми production mounts только на чтение.
Имя не содержит `nginx`, чтобы штатный Certbot hook не выбрал тестовый контейнер для перезапуска.
SSL и HTTP-проверки направлены во внутренний адрес кандидата с настоящим доменным именем и проверкой сертификата.

- Старый и новый Nginx успешно принимают новую конфигурацию; предупреждения об устаревшем `listen … http2` отсутствуют.
- HTTP/2 и маршрутизация пяти доменов совпали с текущим production:
  `insflow.ru`, `www.insflow.ru`, `zs.insflow.ru`, `insflow.tw1.su`, `zs.insflow.tw1.su`.
- **20 прикладных проверок прошли:** чтение/временная запись PostgreSQL с откатом, отсутствие ожидающих миграций,
  реальные HTTPS-страницы сотрудника, PDF, авторизованные HEAD/Range документа с проверкой байтов,
  `private/no-store`, отзыв временной сессии. Без авторизации документ недоступен;
  основной домен и прямой `/_protected_media/` возвращают 404.
- Два обычных Excel-сценария явно пропущены: нет готового свода с действующими предложениями.
  Обе Excel V2 выгрузки отдельно проверены под существующим суперпользователем в read-only транзакциях.
- Временная сессия удалена. Бизнес-данные, роли, пароли и статусы не менялись; обычные HTTP audit-записи остаются.
- В данных на момент проверки: 403 заявки, 403 свода, 4 405 предложений, 1 947 ответов; PostgreSQL 15.19.

Тестовый контейнер удаляется после проверки кандидата. На Mac Docker и тяжёлые тесты не запускаются.

## Критерии завершения выкладки

Кандидатный прогон не подменяет проверку реального production. После обязательного CI и штатного deploy:

1. Сверить Git SHA сервера/сборки приложения, image ID и версию работающего Nginx с закреплённым образом.
2. Проверить healthy контейнеры, TLS/HTTP/2, страницы, статические файлы и защищённые документы.
3. Повторить прикладные проверки и проверить отсутствие новых 5xx/Traceback в рабочем интервале.
4. Подтвердить работу внешнего монитора и доступ Certbot к новому контейнеру.

Окончательные результаты фиксируются в pull request и GitHub Actions выпуска, а безопасные операторские
артефакты — в каталоге `insflow-nginx-upgrade` за 12.11.2026. Пароли, cookies и клиентские файлы туда не выводятся.
