### Различие сериализации Compose

В JSON candidate Compose у трёх Nginx bind mounts прежнее `create_host_path: true` оказалось
пропущено, с представлением `bind: {}`. Причина подтверждена в upstream compose-go 2.16.2:
`CreateHostPath` имеет тип `OptOut`, значение по умолчанию `true` и JSON-тег `omitzero`.
Это не означает переключение на `false`.

Синтетическая проверка подтвердила эквивалентность отсутствующего значения и `true`; явное `false`
сохраняется как `false`. Все остальные поля конфигурации совпали при строгом сравнении.
Такая нормализация разрешена только для указанного поля; остальные расхождения не игнорируются.
[Исходник compose-go 2.16.2](https://github.com/compose-spec/compose-go/blob/v2.16.2/types/types.go),
[спецификация bind/create_host_path](https://docs.docker.com/reference/compose-file/services/#volumes).

2. Штатно остановить четыре существующих контейнера: сначала frontends, затем `web`, последним `db`.
   После этого остановить Docker и containerd.
3. Создать описанный выше холодный архив метаданных; зафиксировать размер и SHA-256.
4. Установить шесть точных cached-пакетов с запретом удаления пакетов и сохранением прежних conffiles
   (`confold`). Автоматические перезапуски посторонних сервисов через needrestart отключить на время операции.
5. Установить описанную обёртку `docker-compose`, запустить containerd и Docker.
6. Запустить **те же существующие контейнеры**: `db` до healthy, затем `web` до healthy,
   после этого `nginx` и `certbot`.
7. Сверить версии, ID контейнеров/образов/mounts и storage driver с baseline. Проверить HTTPS,
   healthz, вход и штатные операции приложения, команды Compose и задания резервирования.

## Ограничения отката

Старые `.deb`, конфигурация и прежний standalone бинарный файл подготовлены для возврата пакетного
и конфигурационного состояния. Перед откатом нужен отдельный разбор фактической ошибки и APT simulation
всего связанного набора. Эти файлы не гарантируют совместимость старого daemon с данными после работы нового.

Полный комплект InsFlow покрывает приложение и его данные; частичный cold metadata archive не заменяет
согласованный полный снимок data-root/VM. Обратную установку старых пакетов нельзя описывать как
проверенное полное восстановление хоста.

Live restore официально ограничен patch-обновлениями и не даёт гарантии работы контейнеров через major upgrade.
Для этой операции выбран управляемый graceful stop/start. При обычном upgrade существующий `overlay2`
сохраняется; включение containerd store меняет расположение/видимость образов и требует отдельного плана.
[Live restore](https://docs.docker.com/engine/daemon/live-restore/),
[daemon data directories](https://docs.docker.com/engine/daemon/),
[containerd image store](https://docs.docker.com/engine/storage/containerd/).
