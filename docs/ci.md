# Обязательные проверки CI

**Подтверждённый результат на 12.11.2026:** 1 070 регрессионных тестов и отдельные
50 PostgreSQL-тестов прошли в [production workflow релиза `1405acc5`](https://github.com/grigra27/flow_insur_requests/actions/runs/43276017086).
Проверка [PR #7](https://github.com/grigra27/flow_insur_requests/pull/7) также прошла все 1 070 регрессионных тестов.
Числа 831/836 в документах перехода от 06.11 относятся к историческим прогонам.

Проверка pull request и job `test` перед production-выкладкой запускают одну команду:

```bash
bash scripts/run_ci_checks.sh
```

Она выполняет `pip check`, `manage.py check`, проверку соответствия моделей файлам миграций и регрессионные тесты
из `scripts/ci_test_labels.txt`. Любая ошибка останавливает job; production-сборка и
выкладка зависят от успешного `test` через `needs: test`.

В `core`, `insurance_requests`, `backup` и `onlineservice` используется discovery всех
тестов: новые тестовые модули этих пакетов автоматически попадают в CI. Для `summaries`
перечислены модули текущих рабочих сценариев: Excel V2, общая подготовка данных и перенаправление прежних ссылок, шаблоны и
загрузка ответов СК, дополнительные риски, статусы, аудит, сделки, аналитика и права.
Исторические ручные проверки и тесты старых интерфейсов не объявлены частью этого набора.
Новый регрессионный модуль `summaries` нужно добавить в этот же список.

Тесты создают свои данные и Excel-файлы; реальные заявки и production-секреты не нужны.
Скрипт принудительно выбирает SQLite и отключает HTTPS, поэтому локальный `.env` не
переключит проверки на рабочий PostgreSQL. Календарные HTTP-запросы в тестах замоканы.
Медиафайлы тестов изолируются настройками Django в отдельном временном каталоге.

Локальный запуск из виртуального окружения:

```bash
SECRET_KEY=ci-only-test-key PYTHON_BIN=venv/bin/python bash scripts/run_ci_checks.sh
```

Дополнительные параметры Django передаются в конец команды, например `--failfast`.
Первый набор запускается последовательно: общий календарный кеш и тестовые настройки
не требуют параллельного выполнения. Это обязательный регрессионный набор, а не
измерение полного покрытия кода тестами.
