# Монтаж/демонтаж спецтехники в ответе СК V2

Блок `equipment_assembly` описывает повреждение или гибель самого застрахованного предмета лизинга при монтаже, демонтаже, сборке и разборке. Существующий блок СМР, его признаки и расчёты сохранены отдельно.

## Поведение

- Каждое вновь формируемое письмо для точного типа `страхование спецтехники` содержит запрос этого покрытия. При доступном пользователю V2 письмо указывает на соответствующий блок Excel-файла. Входящий Excel лизинговой компании не меняется.
- Просмотр заявки или уже сохранённого письма не изменяет письмо. Новый текст появляется при явном формировании письма либо при первом открытии ещё не сформированного письма.
- В персональном шаблоне V2 новый блок обязателен для спецтехники с даты запуска; для остальных запросов он серый и закрыт для ввода. В общем резервном шаблоне он открыт с пояснением условия заполнения.
- Пять именованных ячеек `resp_equipment_assembly_*` соответствуют пяти полям `InsurerResponse`: статус, тариф, премия, порядок/база начисления, ограничения/условия. Версия остаётся V2. Адреса B2, B3, F2 и строк 6–10 не меняются. Динамический шаблон не требует пересборки статического V1-файла.
- Статусы: `included`, `separate`, `declined`, `not_applicable`. Пустое значение означает отсутствие данных.
- При `separate` нужен положительный тариф или премия и непустой порядок/база расчёта. Свободный текст должен объяснять базу тарифа и период/операцию для премии. При `not_applicable` обязательна причина в ограничениях/условиях. Отрицательные, нечисловые, бесконечные значения, NaN и неизвестные статусы отклоняются. При остальных статусах тариф, премия и их основание очищаются.
- Тариф в БД хранится в процентных пунктах (`0.15` = `0,15%`, до четырёх знаков). Числовая Excel-ячейка с форматом `%` преобразуется из доли в процентные пункты; текст `0,15%` и обычная числовая ячейка `0.15` также поддерживаются. Премия хранится с копейками.
- Импорт и ручное редактирование используют один валидатор. Частичное ручное изменение сначала объединяется с сохранёнными полями конкретной СК. Ошибка импорта возникает до создания предложений, ошибочная правка не изменяет прежний ответ.
- Карточка свода показывает обе величины, основание расчёта и условия. В клиентском и полном Excel-своде V2 есть колонка «Монтаж/демонтаж»; основание и ограничения попадают в «Комментарии». Доплата не входит в годовые премии, формулы ИТОГО и сортировку предложений.

## Дата и совместимость

`EQUIPMENT_ASSEMBLY_SINCE` — фиксированная дата в формате `YYYY-MM-DD`, по умолчанию `2026-11-10`. Дата создания заявки сравнивается по Москве, включая весь указанный день. Настройка передаётся контейнеру `web` через `docker-compose.yml`. Некорректная или пустая дата останавливает запуск приложения.

GitHub Actions пересоздаёт серверный `.env` при выпуске. Дата включена в его генератор: берётся из repository variable `EQUIPMENT_ASSEMBLY_SINCE`, при её отсутствии — `2026-11-10`. Для изменения production-даты через Actions нужно менять эту переменную, а не только серверный `.env`. До сборки и выкладки pipeline также выполняет 50 тестов блока на отдельном PostgreSQL 15.

Перед production-выпуском нужно явно установить фактическую дату начала требования. Если выпуск происходит в середине дня, учесть уже созданные в этот день заявки со старыми шаблонами: граница действует с 00:00 МСК, а не с момента перезапуска. Для таких заявок потребуется актуальный ответ либо заранее согласованная дата начала со следующего дня. После запуска границу не сдвигать.

Существующие настройки не переопределяются: `RESPONSE_TEMPLATE_V2_FOR_ALL` управляет доступностью V2 и строгим контуром, `RESPONSE_TEMPLATE_V2_SINCE` — общим переходом на V2. При локальной проверке вне тестов они равны `True` и `2026-10-08`. При выключенном первом флаге строгий контур остаётся у суперпользователя.

Заявки до `EQUIPMENT_ASSEMBLY_SINCE` не требуют нового блока. Ранние V2-файлы без новых именованных ячеек для них принимаются с прежними правилами остальных блоков. Для V1 действует прежняя общая граница перехода на V2: новая настройка не разрешает V1 там, где он уже был запрещён. Исторические ответы не требуют массовой правки.

Повторный файл с новым годом обновляет общие поля того же `InsurerResponse`. Существующая защита от дублирования одной пары «СК + год» сохранена: повторный импорт уже имеющегося года не заменяет годовое предложение. Для исправления общих условий можно использовать ручное редактирование на карточке.

## Миграция

`summaries/0036_insurer_response_equipment_assembly` добавляет пять полей. Тариф и премия допускают `NULL`, остальные поля — пустую строку. Переноса и перерасчёта старых данных нет. Модель `InsuranceOffer` не изменена.

На отдельной SQLite в памяти проверен переход с 0035 на 0036 при наличии исторического ответа: новые поля пусты; прежние СМР и перевозка сохранены. Все автоматизированные проверки выполняются на изолированной тестовой БД, локальная рабочая и production-БД не изменялись.

## Безопасный production-выпуск (только по отдельной команде владельца)

1. Проверить свежую восстанавливаемую резервную копию БД и документов по действующему регламенту. Подготовить проверенный образ приложения и обновлённый Compose-файл.
2. В серверном `.env` установить `EQUIPMENT_ASSEMBLY_SINCE=YYYY-MM-DD` на фактическую московскую дату начала требования. Сохранить прежние значения и поведение `RESPONSE_TEMPLATE_V2_FOR_ALL` и `RESPONSE_TEMPLATE_V2_SINCE`; не менять общую границу V2 ради нового блока.
3. Проверить образ и настройки в окружении развёртывания. На время миграции и переключения остановить `web`, чтобы прежний процесс не создавал ответы без новых полей. Выполнить из нового образа только штатные миграции:

   ```sh
   docker compose run --rm --no-deps --entrypoint python web manage.py check
   docker compose run --rm --no-deps --entrypoint python web manage.py migrate --plan
   docker compose stop web
   docker compose run --rm --no-deps --entrypoint python web manage.py migrate --noinput
   docker compose up -d --no-deps web
   ```

   `web` берётся из подготовленного нового образа. Штатный `entrypoint.sh` также выполняет `migrate` и `collectstatic` при запуске; повторное применение миграций безопасно. До успешного запуска нового `web` Flow будет временно недоступен.
4. Проверить `/healthz/`, журналы запуска и фактические три настройки через Django settings, не выводя другие переменные окружения. Старые сохранённые письма не перегенерировать массово.
5. При неудачном выпуске сохранить уже полученные ответы. Старый образ не запускать для записи поверх новой схемы без проверки совместимости: новые текстовые колонки имеют `NOT NULL`. Обратная миграция удаляет новые сведения. Восстановление согласованного комплекта кода и БД из резервной копии либо исправляющий выпуск проводить по действующему регламенту.

## Ручные проверки после выпуска

1. Создать синтетическую заявку на спецтехнику без дополнительных признаков. Сформировать письмо: новый абзац встречается один раз и указывает на блок ответа. Повторить формирование и проверить отсутствие дублирования.
2. Скачать персональный и резервный шаблоны. В Excel выбрать каждый статус. Для доплаты указать `0,15%` и/или премию с базой/периодом; сохранить `.xlsx` и загрузить в Flow. Проверить обе суммы и условия на карточке.
3. Оставить доплату без суммы/тарифа, затем «Не применимо» без причины: импорт и ручное сохранение должны отклоняться. Сменить доплату на «Включено» или «Не страхуем»: прежняя стоимость должна исчезнуть.
4. Открыть заявку до даты запуска и её сохранённое письмо. Письмо не меняется; ранний V2-ответ без блока загружается. Для исторической заявки до общей границы V2 проверить прежний V1-сценарий.
5. Проверить КАСКО и имущество: абзаца в письме нет, блок в персональном файле не требует заполнения, данные из него не импортируются.
6. На спецтехнике одновременно включить СМР и перевозку, заполнить их независимо. Скачать клиентский и полный своды V2. Проверить колонку, комментарии, отсутствие ответа «Нет данных», неизменность ИТОГО при изменении только доплаты.
7. Проверить своды с 1, 2 и несколькими СК, оба варианта, длинные ограничения, экран и предварительный просмотр печати в рабочей версии Microsoft Excel.
