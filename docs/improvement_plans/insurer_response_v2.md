## 0. Суть

Шаблон ответа страховщика становится **одним универсальным файлом**: базовый блок (как сейчас — СК,
территория, примечание, годы 1–5, варианты 1/2) есть во всех ответах, ниже — **дополнительные блоки**,
которые заполняются по условию заявки: осмотр (всегда), риски РНПК (спецтехника и имущество), перевозка
(если в заявке есть перевозка). Набор блоков описан **в одном реестре в коде**, из которого работают
генерация шаблона, загрузка и валидация, карточка свода, ручная форма и свод V2. Новый блок в будущем —
одна запись в реестре.

Всё новое разрабатывается **параллельно и скрыто** (только суперпользователь), как свод V2: сотрудники
продолжают работать с текущим шаблоном и текущим сводом V1, пока V2 не будет готов.

## 2. Что есть сейчас

**Заявка** (`InsuranceRequest`) — условия для блоков уже собираются парсером заявки:

| Поле | Значение для блоков | На проде (332 заявки) |
|---|---|---|
| `insurance_type` | РНПК — для спецтехники и имущества | КАСКО 223, спецтехника 81, имущество 26, другое 2 |
| `has_transportation` + `transportation_departure/destination/days` | блок «Перевозка», маршрут подставляется в шаблон | 6 (имущество 4, спецтехника 1, другое 1) |
| `has_construction_work` | кандидат: блок «СМР» | 3 |
| `has_casco_ce` | кандидат: доп. риски C/E | 75 |

**Письмо страховщику** (`core/templates.py`) про РНПК уже спрашивает («Будут ли включены в полис риски
РНПК») для спецтехники и имущества, про перевозку — с маршрутом.

**Ответ СК** — отдельных полей нет, всё уходит в «Примечание» свободным текстом. По примечаниям первого
года: РНПК — 136 из 366 ответов по спецтехнике, 22 из 50 по имуществу, 33 по КАСКО; перевозка — 52
упоминания («Перевозка груза: 5 330 руб.»); осмотр — 147 по КАСКО, 40 по спецтехнике; согласование
СБ/андеррайтера — 131.

**Хранение ответа** — данные уровня «ответ СК целиком» (территория, примечание, файл) дублируются в каждой
годовой строке `InsuranceOffer`; для территории есть сервис синхронизации между годами
(`summaries/services/offer_territory.py`).

**Шаблон** — `templates/flow_answer_template.xlsx`, собирается `scripts/build_flow_answer_template.py`;
парсер `ExcelResponseProcessor` читает фиксированные адреса B2, B3, F2, A6:J10.

## 3. Шаблон V2

### 3.1 Раскладка (одна для персонального и общего)

```
Строка 1        Заголовок (в персональном — «… на запрос <ДФА>»), логотип брокера
Строки 2–10     БАЗОВЫЙ БЛОК — адреса НЕ меняются (B2 СК, F2 примечание, B3 территория, A6:J10 годы)
Строка 12       Полоса «Запрос <ДФА> · вид · объект · перевозка: маршрут» (в общем — пояснение)
Блок «Осмотр предмета лизинга»       всегда            [Да/Нет ▾]
Блок «Риски РНПК»                    спецтехника, имущество   [статус ▾] + комментарий
Блок «Перевозка»                     есть перевозка    маршрут (из заявки, только чтение) + сумма, ₽ + условия
… будущие блоки
Как заполнить (обновлённая инструкция) · Образец
Скрытый лист _meta: template_version=2, summary_id
```

### 3.2 Состояния блока

| Состояние | Где | Вид |
|---|---|---|
| Обязателен | персональный, условие выполнено; «Осмотр» — везде | жёлтые поля, плашка «ЗАПОЛНИТЕ — обязательно для этого запроса» |
| Не требуется | персональный, условие не выполнено | серые поля «—», закрыты от ввода, плашка «НЕ ТРЕБУЕТСЯ — не заполняйте» |
| По условию | общий шаблон | жёлтые поля, плашка с условием («Заполняется, если вид страхования — спецтехника или имущество») |

### 3.3 Адресация

- Базовый блок — прежние фиксированные адреса: старые копии и V1-загрузка не ломаются.
- Новые поля — **именованные ячейки Excel** (`resp_inspection`, `resp_rnpk_status`, `resp_rnpk_comment`,
  `resp_transport_cost`, `resp_transport_terms`). Парсер читает по имени, блоки можно двигать.
- Скрытый лист `_meta` (veryHidden): версия шаблона и номер свода. По версии парсер выбирает правила;
  по номеру свода — подсказка, если файл загружают не в тот свод (предупреждение, не отказ).

### 3.4 Инструкция в шаблоне

Пункт про территорию переписан: «осмотр, риски РНПК и перевозку — в отдельных блоках ниже; прочие условия
(согласование СБ и т. п.) — в „Примечании“». Добавлены пункты: какие блоки заполнять (по плашкам / по
условию) и «обязательные блоки не оставляйте пустыми — иначе ответ не будет принят». Образец заполнения
дополняется заполненными блоками.

## 4. Реестр блоков

Файл `summaries/response_sections.py` — единственное место, где описан блок:

```python
ResponseSection(
    key='rnpk',
    title='Риски РНПК',
    condition=lambda request: request.insurance_type in ('страхование спецтехники', 'страхование имущества'),
    condition_text='Заполняется, если вид страхования — спецтехника или имущество',
    fields=[
        Field('rnpk_status', 'Риски РНПК в полисе', kind='choice',
              choices=['Включены в полис', 'Не включены', 'Требуется согласование'], required=True),
        Field('rnpk_comment', 'Комментарий', kind='text', required=False),
    ],
    summary_column='Риски РНПК',   # колонка в своде V2
)
```

Блоки на старте: `inspection` (всегда), `rnpk`, `transport`. Из реестра работают: генератор шаблона,
парсер/валидация, сохранение, карточка свода, ручная форма, свод V2, справка.

## 5. Хранение: таблица «Ответ СК»

Новая модель `InsurerResponse` (рабочее имя), одна строка на пару «свод + компания»:

| Поле | Тип | Назначение |
|---|---|---|
| `summary`, `company_name` | FK, строка | ключ, `unique_together` |
| `template_version` | int | 1 — старый шаблон/ручной ввод, 2 — шаблон V2 |
| `inspection_required` | bool, null | блок «Осмотр» |
| `rnpk_status` | choice, null | блок «Риски РНПК» |
| `rnpk_comment` | text | |
| `transport_cost` | decimal, null | блок «Перевозка» |
| `transport_terms` | text | |
| `source_file` | file | исходный файл (сейчас пишется в `InsuranceOffer.attachment_file` — со временем сюда) |
| `received_at`, `created_by` | | |

Годовые `InsuranceOffer` не меняются. Территория и примечание пока остаются в предложениях (их перенос —
отдельная задача, §10). Значения блока, который по заявке не требуется, **не сохраняются**.

## 6. Загрузка и валидация (V2)

1. Определить версию файла по `_meta` (нет листа — V1).
2. Базовый блок — как сейчас (тот же парсер; в т. ч. обязательная территория).
3. Для каждого блока реестра: нужен ли он **по заявке свода** (а не по тому, что заполнил страховщик —
   это важно для общего шаблона).
   - нужен и пуст / значение не из списка → **отказ** с понятным текстом, по образцу территории:
     «Ответ СК «Согаз» не загружен: не заполнен блок „Риски РНПК“. Запросите у страховой компании
     корректное предложение…»;
   - не нужен → значение игнорируется.
4. Сохранение: годовые предложения + строка «Ответ СК» — в одной транзакции.
5. Файл V1 (старый шаблон) в своде, где V2-блоки обязательны: в контуре V1 — грузится как сейчас; в контуре
   V2 — грузится базовый блок, строка «Ответ СК» помечается «данные блоков не получены» (не отказ —
   иначе нельзя будет работать со старыми копиями; решение уточнить, §10).

## 8. Параллельный контур V1/V2

Принцип — как у свода V2: **ничего, что видят сотрудники, не меняется**, пока V2 не открыт.

| | V1 (сотрудники) | V2 (суперпользователь) |
|---|---|---|
| Шаблон ответа | кнопка «Скачать актуальный шаблон ответа» — текущий файл | отдельная тестовая карточка (как у свода V2): «Тест: шаблон ответа V2 (персональный)» + ссылка «общий шаблон V2» |
| Загрузка | текущий путь, без изменений | тот же эндпоинт: файл с `_meta.template_version=2` разбирается расширенным путём; суперпользователь может загружать V2-файлы в любой свод — базовый блок попадает в обычные предложения, свод V1 продолжает работать |
| Данные | `InsuranceOffer` | `InsuranceOffer` + `InsurerResponse` |
| Свод | V1 (шаблоны xlsx) | свод V2 с новыми колонками |

Защита: если сотрудник без прав всё-таки загрузит V2-файл — базовый блок загружается как обычно (V1 его
понимает, адреса те же), данные блоков сохраняются молча; отказ по обязательным блокам действует только в
контуре V2. Флаг открытия — настройка `RESPONSE_TEMPLATE_V2_FOR_ALL` (по умолчанию `False`).

   без». Сейчас — одно на ответ.
2. Осмотр в своде V2: колонка всегда, или только когда хотя бы одна СК ответила «Да»? Как сочетать с

   комментарии свода V1/V2)?
3. Старая копия шаблона в контуре V2, когда блоки обязательны: принимать базовый блок с пометкой (предложение
   §6.5) или отклонять?
4. Кандидаты в блоки: СМР (3 заявки), доп. риски КАСКО C/E (75), согласование СБ/андеррайтера (131
   упоминание в примечаниях), ОСВР.
5. Перенос территории, примечания и исходного файла из годовых предложений в «Ответ СК» — когда.
6. Письмо страховщику (`core/templates.py`): после открытия V2 сослаться на блоки шаблона вместо просьбы
   «указать, будут ли прописаны риски РНПК».
