# Заявка для страховой: чего не хватает в данных

Дата: 2026-09-28.
Статус: план, до проектирования и кода.
Связано: [own_insurance_request_form.md](own_insurance_request_form.md).

## Контекст

PDF «Заявка для страховой» (`insurance_requests/application_export.py`,
шаблон `application_pdf.html`) переделан в фирменный документ ОН-ЛАЙН брокер:
A4 альбомная, одна страница, логотип и цвета бренда (красный `#BA122B`,
графитовый `#495E5F`), шрифт PT Sans. В документ выводится всё, что сейчас
хранится в заявке и нужно андеррайтеру, включая исходную строку объекта из
заявки лизингополучателя и явные «Нет» по флагам рисков.

Цель — отправлять страховщикам этот документ вместо исходного Excel
лизингополучателя. Ниже — данные, которых для этого не хватает. Разбор сделан
по 120 заявкам Parser V2 на проде (заполненность полей и содержимое
`additional_data.parser_v2.parsed_payload`).

## 1. Срок лизинга — правка парсера

**Проблема.** В заявке есть только `insurance_period` = «на весь срок
лизинга», без длительности. При этом мы просим у страховщика премию
«по каждому году» — он не знает, на сколько лет считать.

**Что сделать.**
- Найти в корпусе исходных Excel, где указан срок лизинга (месяцы и/или даты
  начала и окончания договора лизинга); проверить оба формата
  (`casco_equipment`, `property`) и вариант ИП со сдвигом строк.
- Parser V2: извлекать срок в месяцах (и даты, если есть), показывать в
  превью для проверки оператором.
- Модель: поля `lease_term_months` (и при необходимости `lease_start_date`,
  `lease_end_date`) с `verbose_name` на русском; миграция.
- PDF: «Срок страхования: на весь срок лизинга (36 мес.)»; число лет
  использовать в блоке «Ответ страховщика».

## 2. VIN, заводской или серийный номер — правка парсера

**Проблема.** Такого поля нет ни в модели, ни в `insured_objects` парсера.
Без идентификатора объекта страховщик не может проверить технику и историю
убытков.

**Что сделать.**
- Найти в корпусе, где лизингополучатели указывают VIN / заводской номер /
  номер рамы / серийный номер (часто в строке описания объекта или отдельной
  колонке).
- Parser V2: извлекать номер на уровне объекта (для партий — у каждого
  объекта свой); валидировать формат VIN (17 символов без I, O, Q),
  остальные номера сохранять как есть.
- Модель: поле `serial_number` (подпись «VIN / заводской номер»).
- PDF: отдельная плитка в блоке объекта.

## 3. Контакты брокера для ответа

**Проблема.** В документе есть только ФИО автора заявки. У пользователей
пустые e-mail, телефона нет вовсе. Страховщику непонятно, куда отвечать.

**Что сделать.**
- Хранить e-mail и телефон сотрудника (профиль пользователя или поля
  `User.email` + отдельная модель профиля для телефона); редактирование в
  админке.
- Общий адрес для ответов (например, ящик отдела) — в настройках.
- PDF: строка «Ответ направляйте: ФИО, телефон, e-mail» в блоке «Ответ
  страховщика».

## 4. Лизингодатель и выгодоприобретатель

**Проблема.** В документе нет наименования и ИНН лизингодателя, а он —
собственник имущества и обычно выгодоприобретатель по договору.

**Что сделать.**
- Уточнить у владельца: один лизингодатель на все заявки или разные
  (по филиалам / компаниям).
- Если один — реквизиты в настройках; если разные — справочник и привязка
  заявки (парсер может определять по шаблону файла или филиалу).
- PDF: блок «Лизингодатель / выгодоприобретатель» рядом с лизингополучателем.

## 5. Реквизиты брокера в подвале

Сейчас в подвале только «ОН-ЛАЙН брокер». Нужны полное юридическое
наименование, ИНН, номер лицензии/реестра, сайт и телефон — взять у
владельца и хранить в настройках.

## 6. Единицы мощности и НДС в стоимости

- `power_or_capacity` хранится числом без единиц («292,31»): неясно, л.с.
  или кВт. Парсер должен сохранять единицы из заголовка колонки.
- Стоимость приобретения: неизвестно, с НДС она или без. Парсер — определять
  по подписи в Excel; модель — флаг `acquisition_cost_includes_vat`.

## 7. Таблица для ответа страховщика

В блоке «Ответ страховщика» пока написано «в прилагаемой таблице Excel» —
это исходный Excel лизингополучателя. Если PDF его заменяет, нужна своя
форма ответа: либо Excel-шаблон, который система генерирует вместе с PDF,
либо вторая страница PDF с таблицей по годам (год, страховая сумма, тариф,
премия, франшиза). Число строк — из срока лизинга (п. 1).

## 8. Качество данных до отправки

Документ уходит страховщику как есть, поэтому ошибки распознавания
становятся видны снаружи. Примеры с прода:
- «Вид деятельности: ЛизингоДАТЕЛЬ» (ОБ-20852-ЛО-АР) — парсер взял не ту
  ячейку;
- «Территория: г, Псков г, Рельсовая ул…» — адрес не нормализован;
- «Менеджер сделки» — это сотрудник лизингодателя; проверить, что подпись
  понятна страховщику.

Предложение: перед отправкой показывать оператору превью PDF и чек-лист
подозрительных значений (связано с валидацией на этапе загрузки).

## 9. Длинные заявки

Документ рассчитан на одну страницу. Очень длинные тексты (старые V1-заявки
с многострочным `vehicle_info`, длинные условия охраны) переносятся на
вторую страницу — это допустимо, но стоит проверить на корпусе и при
необходимости ужимать шрифт автоматически.
