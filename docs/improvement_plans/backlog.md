## 1. Депрекейт V1 и старых полей объекта (фаза D) — в работе

Источник: [legacy_object_fields_deprecation.md](legacy_object_fields_deprecation.md) (фазы A–C сделаны).
Решение владельца 2026-10-13: делать сейчас.

Факты на проде (2026-10-13, только чтение):
- 343 заявки: 201 загружена старым загрузчиком V1 (10.11.2025–10.06.2026), 142 — парсером V2 (с 09.06.2026).
  Через V1 (`/upload-old/`) за последние 60 дней не загружено ни одной заявки.
- У всех 201 заявки V1 объект хранится **только** в `vehicle_info` (структуры и `object_description` нет);
  `asset_status` заполнен у 72 из них. У V2-заявок `object_description` есть у всех; `vehicle_info` — у 20,
  `asset_status` — у 54 (запасная запись, когда состояние объекта не распознано).
- Ссылки в коде: `vehicle_info` — 16 файлов (+27 файлов тестов), `asset_status` — 22 файла, включая схему
  JSON v2 (`docs/insurance_request_format_package/insurance_request_schema_v2.json`) и примеры к ней.

Шаги (каждый — отдельный коммит, удаление столбцов — отдельным деплоем после бэкапа):
1. **D1. Убрать загрузку V1:** маршрут `/upload-old/`, представление `upload_excel`, `core.excel_utils.ExcelReader`
   и его тесты (плюс использования в `scripts/coverage_audit.py`, `analytics_parser_edits.py`).
2. **D3. Перенос данных** командой с отчётом и `--apply`: у заявок без `object_description` —
   `object_description = vehicle_info` (текст как есть, без потерь); `condition` из `asset_status`
   («новое» → new, «б/у» → used), значения, которые не разбираются, — в отчёт.
3. **D2. Убрать чтения и запись старых полей:** запасные ветки в `models.py`, `to_dict()`, экспорт, админка,
   форма редактирования, учёт правок, парсер (запасная запись `asset_status`), схема JSON v2 — решить,
   выпускать ли схему v3 без `asset_status` (внешний контракт).
4. **Удаление столбцов** `vehicle_info` и `asset_status` миграцией — после бэкапа и проверки на копии данных прода.
